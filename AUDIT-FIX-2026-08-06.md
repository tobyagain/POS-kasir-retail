# Audit Fix — 6 Agustus 2026

## Bug Kritis yang Diperbaiki

### 1. ✅ INV-4 KEMBALIAN TIDAK DIKURANGI (paling kritis)
**Sebelum:** `kasSistem = modalAwal + tunaiDibayar + masuk - keluar`
**Sesudah:** `kasSistem = modalAwal + (tunaiDibayar - kembalian) + masuk - keluar`

- **File:** `src/core/shift.js:10-18`
- **Impact:** Kas sistem selalu lebih besar dari fisik. Laporan shift salah.
- **Fix:** `totalTunaiPenjualan()` sekarang hitung netto tunai (`tunaiDibayar - kembalian`).

### 2. ✅ RACE CONDITION: nested onsuccess di transaksi
**Lokasi:** `saleService.js:61-85`, `purchaseService.js:45-78`, `saleService.js:108-132`

**Sebelum:** `forEach` + nested `onsuccess` → operasi async bisa selesai **setelah** `tx.oncomplete`
**Sesudah:** `for...of` loop sinkron, operasi batch dalam satu tick transaksi.

- **Impact:** Stok belum update tapi transaksi sudah commit → data loss.
- **Fix:** Ganti `forEach` jadi `for...of`, tambah ponytail comment.

### 3. ✅ DUPLIKASI LOGIK KAS TUNAI
**File:** `src/ui/shift.js:95-104`

**Sebelum:** UI hitung manual `tunaiDibayar - kembalian` (berbeda dari core)
**Sesudah:** Import `hitungKasSistem()` dari core.

- **Impact:** Bug laten kalau rumus core diubah, UI tidak ikut.
- **Fix:** Single source of truth, konsisten dengan test.

### 4. ✅ TUTUP SHIFT: exclude void tidak konsisten
**File:** `src/services/shiftService.js:40-52`

**Sebelum:** Filter void di dalam callback IDB (`.filter(s => !s.void)`)
**Sesudah:** Ambil semua, filter void setelah Promise resolve.

- **Impact:** Kalau ada void, `kasSistem` dobel hitung tunai void.
- **Fix:** Filter eksplisit setelah fetch, jelas di audit.

### 5. ✅ VALIDASI KATEGORI CASHFLOW
**File:** `src/services/cashflowService.js:8-12`

**Sebelum:** Kategori bebas string, tidak divalidasi
**Sesudah:** Throw error kalau kategori tidak ada di `KATEGORI[jenis]`.

- **Impact:** Laporan `labaBersih` salah kalau kategori typo/bebas.
- **Fix:** Strict validation, error message list kategori valid.

### 6. ✅ DEAD CODE: resetKeranjang() referensi elemen lama
**File:** `src/ui/kasir.js:532-550`

**Sebelum:** Cari `#input-barcode` & `#input-search` (tidak ada)
**Sesudah:** `#input-search-produk` (elemen setelah merge unified search).

- **Impact:** Fokus input gagal setelah reset keranjang.
- **Fix:** Hapus `inputMode` switch, langsung ke elemen yang benar.

### 7. ✅ TEST COVERAGE: INV-5 edge case
**File:** `tests/shift-edge.test.js` (baru)

**Sebelum:** Tidak ada test "jual tanpa shift"
**Sesudah:** Test `shiftId null` harus throw error.

- **Impact:** Invarian INV-5 tidak terverifikasi otomatis.
- **Fix:** Test 17/17 passing (dari 16).

## Bug yang Belum Diperbaiki (Perlu Keputusan Bisnis)

### 8. ⚠️ COUNTER RESET BULANAN TIDAK IMPLEMENTASI
**Status:** Deferred — fitur belum jelas.

**Lokasi:** `saleService.js:25`, `purchaseService.js:15`

**Sebelum:** `resetBulanan` dihitung tapi counter tidak pernah reset.
**Kode sekarang:**
```js
const resetBulanan = counter.periode !== periode;
const seq = resetBulanan ? 1 : counter.next;
```

**Bug:** Counter naik terus walau ganti bulan (seq tetap naik dari `counter.next`).

**Fix yang benar:**
```js
const seq = (counter.periode !== periode) ? 1 : counter.next;
```

**Tapi:** `meta.resetStrukBulanan` (setting user) belum dipakai. Perlu keputusan:
- Reset bulanan otomatis (periode YYMM ganti → seq = 1)?
- User pilih via setting?
- Tidak reset sama sekali (counter global)?

**Rekomendasi:** Tunda sampai user test produksi 1 bulan, lihat preferensi reset atau tidak.

### 9. ⚠️ SHIFT CLOSED TIDAK LOCK CASHFLOW/SALE
**Status:** Deferred — validasi shift.status perlu di semua entry point.

**Sekarang:** `catatCashflow()` & `simpanPenjualan()` cek shift open, tapi tidak ada guard kalau shift sudah closed.

**Risk:** Edit manual DB (dev tools) bisa insert data ke shift lama.

**Fix:** Tambah validasi `shift.status === 'open'` di semua service entry point. Low priority (production tidak ada akses dev tools).
